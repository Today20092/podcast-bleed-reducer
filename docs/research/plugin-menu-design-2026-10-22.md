## Primary documentation

- [Melda MAGC manual](https://www.meldaproduction.com/download/documentation/MAGC.pdf): Settings opens additional plugin settings; GUI/style, engine and global configuration have distinct purposes, with detailed help. This supports separating configuration from general support links. The manual is current online documentation, not a version-matched runtime capture of the installed wrapper.
- [TDR Prism manual](https://docs.tokyodawn.net/tdr-prism-manual/#Standard_Context_Menu): contextual options use a menu, while Settings opens a dialog. Clicking outside dismisses the menu. Its contents distinguish analyzer, graphics, size/scale and state operations. This supports concise grouped commands and predictable dismissal without requiring a submenu for every destination.
- [TDR Nova manual](https://docs.tokyodawn.net/nova-manual/#Standard_Context_Menu): context commands include state operations with keyboard hints; Help/About remain in Settings. The documented menu dismisses on an outside click. Its categories reflect the plugin's real features, not decoration.
- Manufacturer menu illustrations were inspected directly: [Prism](https://docs.tokyodawn.net/wp-content/uploads/2024/07/prism-standard-context-menu.png) shows a consistent row column, separators, selected scale checkmark and submenu arrows; [Nova](https://docs.tokyodawn.net/wp-content/uploads/2020/07/nova_standard_context_menu_updated_2.1.2.png) shows aligned rows, separators and state-command hints. These are published illustrations, not captures of the installed plugins. They support row alignment/grouping; they do not reveal hover/focus animation or keyboard handling. Local reference copies remain outside the repository.
- [Earlier Pro-L 2 shipped-help investigation](pro-l2-edge-scroll-2026-10-22.md) establishes the same installed binary and the distinction between embedded help and measured execution. No scrolling or rendering changes are part of this menu task.

## CleanSlate decisions

Use the existing native Iced supporting-command surface and house palette. Seven destinations do not warrant another submenu layer. Present equal-width, left-aligned rows rather than separate blue action-sized buttons. Group Settings/Keyboard shortcuts, Help/GitHub/Report a bug, and About/Close with quiet separators. Keep effective shortcut hints in a separate right-aligned column, so remapping does not disturb label alignment. Show keyboard selection through the existing selected/hover/focus styling; do not shift labels by adding a leading selection character.

Size the panel to its contents, with bounded scrolling only when the window requires it. Preserve all destinations and existing keyboard ownership: Tab/Shift+Tab/Up/Down cycle rows, Enter activates, Escape dismisses. Add outside-click dismissal at the menu's scrim; the panel consumes its own pointer events so clicking inside cannot reach the workspace. Settings and About retain their established dialog behavior. No audio/project mutation, invented menu options or toolkit/dependency change is needed.

The existing menu has no unavailable destinations. Keep the house disabled-row rendering available through its button styling; do not manufacture a disabled command merely to fill a screenshot. Enlarged operating-system text and physical assistive-technology behavior require native inspection where supported. Exact plugin geometry, easing, keyboard behavior and implementation remain unmeasured; these layout choices are CleanSlate decisions informed by the documented organization.
